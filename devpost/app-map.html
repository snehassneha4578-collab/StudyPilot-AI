Code Tour and App Map · StudyPilot AI

From study details to a saved plan

StudyPilot AI is a client-side study planner. Its deterministic scheduler creates a complete timetable from subjects, topic difficulty, exam dates, and daily study hours. React views show the schedule and real progress; browser localStorage restores it after refresh.

Reference route: this is a code map for navigating the implementation, not a claim that a guided editor tour was completed. Source snapshot: current local workspace; no Git commit exists.

One action through the app

Three-stop reference route

1. Capture input

src/components/PlanSetupForm.tsx — find handleGenerate. It takes one browser-local date snapshot, validates the current form values, then asks for a schedule.

2. Enforce the rules

src/lib/planner.ts — find validatePlanInput and generateSchedule. Pure functions check date/workload feasibility and build sessions before each exam, or return a conflict instead of a partial plan.

3. Save and reflect

src/context/StudyPlanProvider.tsx connects actions to storage.ts; stats.ts derives displayed analytics from sessions.

To change this, start here

  • Study duration estimates or scheduling rules: src/lib/planner.ts and the SchedulingPolicy type in src/types/study.ts.
  • Subject/topic form fields: src/components/PlanSetupForm.tsx.
  • Progress calculations: src/lib/stats.ts; presentation: src/components/ProgressInsights.tsx.
  • Saved-data format and recovery messages: src/lib/storage.ts.

A practice to reuse

The exam-date issue showed why date validation and scheduling should use the same date snapshot. The form now captures one local calendar date per submission; regression tests cover today, tomorrow, past, and malformed dates in src/lib/planner.test.ts. On another project, turn a date boundary into an explicit example and test the boundary before changing validation rules.

Run again (PowerShell): npm.cmd ci, then npm.cmd run dev. Run checks with npm.cmd run test and npm.cmd run build.
